## Worum geht es?
Ein **Branch** ist ein Seitenarm deines Projekts: Du kannst dort Neues ausprobieren, ohne die funktionierende Version auf `main` zu gefährden. Ein **Pull Request** (PR) ist der Antrag, die Änderungen zurück in `main` zu übernehmen – das nennt man **Merge**.

## Warum ist das wichtig?
So arbeiten praktisch alle Software-Teams. Ein PR zeigt übersichtlich alle Änderungen und ist der Ort für Feedback – von Teammitgliedern oder von einer KI, die deinen Code prüft. Geht ein Experiment schief, löschst du einfach den Branch.

## So gehst du vor
1. Lege einen neuen Branch mit sprechendem Namen an, z. B. `feature/kontaktformular`.
2. Lass die KI dort eine kleine Änderung bauen und committe sie.
3. Pushe den Branch zu GitHub und öffne einen Pull Request.
4. Beschreibe im PR, was du geändert hast und warum.
5. Klicke auf **Merge**.

## Tipp: So fragst du Claude Code
> „Leg einen Branch feature/… an, setz dort die User Story … um, committe und öffne mit gh einen Pull Request mit einer verständlichen Beschreibung.“
